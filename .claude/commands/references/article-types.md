# 記事タイプ定義

`/write` と `/zenn-review` が参照する、ジャンル別の記事構造・レビュー基準の単一ソース。

---

## ブランド軸（全ジャンル共通）

キャッチコピー：「製造現場の課題を調査から実装まで——Python/LLM活用の記録」

すべての記事はこのブランド軸に沿って書く。
記事を通じて以下の3層が積み重なるように意識する：

- **表層**（タイトル・冒頭）：検索でヒットする具体的な技術×製造業の組み合わせ
- **中層**（記事の構成）：現状調査→可視化→設計→実装→運用のプロセスを毎回見せる
- **根層**（積み重ね）：断片情報から全体像を掴んで動かせる人という認知を時間をかけて作る

---

## ジャンル一覧

| ジャンル識別子 | 名前 | 内容例 |
|---|---|---|
| `field-analysis` | 現状調査・可視化・設計 | 業務フロー整理、不良要因ツリー、Mermaid構造化 |
| `data-etl` | データ分析・ETL | データパイプライン構築、製造データ分析、コンペ参加記 |
| `python-impl` | Python実装 | 画像検査・計測・OpenCV系の実装 |
| `ai-llm` | AI/LLM活用 | Claude壁打ち、LLMエージェント、仕様駆動開発 |
| `daily-hack` | 日常課題解決 | 製造業以外の個人課題（賃貸スコアリング等） |

## field-analysis（現状調査・可視化・設計）

製造現場の複雑な課題に対して、現状調査・可視化・構造化から入り、全体像を把握して設計に落とした記事。

**記事の型:**
```
① 混沌の描写
   スパゲッティ化した業務・断片情報が散らばっている状態を描く
② 調査・ヒアリングのプロセス
   どう情報を集め、どう繋ぎ合わせたか
③ 可視化と全体像の把握
   Mermaid・因果ツリー・フロー図など、構造を見える形にした過程
④ 設計への落とし込み
   全体像から「何から手をつけるか」を決めた判断
⑤ 実装・適用（ある場合）
   設計を現場に適用したプロセス
⑥ 残課題と次のステップ
```

**レビュー時のチェックポイント:**
- 「混沌→構造化」のビフォーアフターが見えるか
- 可視化ツール（Mermaid等）が使われているか
- 「なぜその構造になったか」の判断プロセスが書かれているか

## data-etl（データ分析・ETL）

製造データのパイプライン構築・分析・モデリングを扱った記事。コンペ参加記もここに含む。

**記事の型:**
```
① 課題・背景
   どんなデータがあり、何を明らかにしたかったか
② データの現状把握
   データの品質・構造・欠損の実態
③ ETL・前処理
   データを使える形にするまでのプロセス（失敗含む）
④ 分析・モデリング
   アプローチの選択と試行錯誤
⑤ 結果と数字
   具体的な成果（精度・順位・改善率）
⑥ 現場への示唆
   分析結果をどう使うか・次のアクション
```

**レビュー時のチェックポイント:**
- 具体的な数字（精度・順位・改善率）が入っているか
- 失敗したアプローチが書かれているか
- 「データを取れば何とかなる」ではなく仮説が先に来ているか

## python-impl（Python実装）

製造業の計測・検査・自動化をコードで解決した実装記事。

**記事の型:**
```
① 現場あるある（共感）
   読者が「これ自分の職場だ」と感じる書き出し
② 課題の深掘り
   品質・属人化・原因特定など、現場を知るからこそ書けるコンテキスト
③ アイデアの核心
   シンプルな原理をフローで。難しいアルゴリズムは不要という安心感
④ 実装
   コードは3ブロック（読み込み・処理・出力）。サンプル画像同梱
⑤ 現場適用ポイント
   キャリブレーション・固定・ログ保存など実運用に必要な視点
⑥ 課題と対応アイデア
   「課題 → 対応アイデア」のセット。段階を示す
```

**レビュー時のチェックポイント:**
- コードが「読み込み・処理・出力」で整理されているか
- サンプル画像・GitHubリンクが用意されているか（ない場合は重大な減点要因）
- 実運用ポイント + 課題対応セットが揃っているか

## ai-llm（AI/LLM活用）

Claude/GPT等との試行錯誤と結果がある体験談、またはLLMエージェントの製造業活用記事。

**記事の型:**
```
① 状況設定
   いつ・何に・どんな条件で挑んだか
② ぶつかった壁
   自力では解決できなかった具体的な問題
③ AIとの試行錯誤
   実際の問いかけと返答・方向転換の瞬間（プロンプト例を含む）
④ 突破口
   何が変わったか・何に気づいたか
⑤ 結果と数字
   定量的な成果（順位・スコア・時間・改善率）
⑥ 読者への問いかけ
   「あなたの現場でも試せる」視点で締める
```

**レビュー時のチェックポイント:**
- AIとの具体的なやり取り（プロンプト例・返答の抜粋）があるか
- 失敗したアプローチが書かれているか（成功談だけはNG）
- ⑤で数字が出ているか

## daily-hack（日常課題解決）

製造業以外の個人課題をPython/AIで解いた記事。

**記事の型:**
上記ジャンルを参考に、テーマ本位で設定する。以下は必須：
```
- 「課題 → 解決」のストーリー構造
- 一次情報三本柱（実数・失敗談・具体シーン）を必ず含む
- 読者が「自分にも使える」と感じる視点で締める
```

**レビュー時のチェックポイント:**
- 課題とソリューションの対応が明確か
- 再現可能か（コード・手順が揃っているか）
