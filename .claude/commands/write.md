# /write — 執筆ハーネス

引数: `$ARGUMENTS`

起動時に必ず CLAUDE.md と `.claude/commands/references/article-types.md` を読む。

---

## Step 1: 企画メモ取得・ジャンル識別・ブランド整合確認

### 1-a. 企画メモ取得

**引数がある場合：**
- Notion の URL → `notion-fetch` で取得。
- 記事スラッグ → `notion-search` で対応する企画メモを探す。

**引数がない場合：**
「Notion に企画メモはありますか？（URL またはスラッグを教えてください）」と確認する。
- ある → 上記と同様に取得。
- ない → 1-a' の企画ヒアリングへ。

---

### 1-a'. 企画ヒアリング（Notion企画メモがない場合）

以下を 1 問ずつ聞いて、記事の骨格を固める。
すでに分かっている情報は聞かない。

1. **テーマ・タイトル案**：「どんな記事を書きたいですか？（仮タイトルでも OK）」
2. **きっかけ・背景**：「なぜこれを書こうと思いましたか？（読者に伝えたい体験や問題意識）」
3. **核心メッセージ**：「読者に一番持ち帰ってほしいことを一言で」
4. **想定読者**：「どんな人に読んでほしいですか？」

ヒアリング完了後、以下の形式で企画メモサマリーを作成して提示し、「この内容で進めますか？」と確認する。

```
タイトル案: ...
ジャンル（仮）: ...
核心メッセージ: ...
想定読者: ...
```

確認が取れたら、`notion-create-pages` で Zenn 運営タスクリスト配下の「💡 記事アイデアDB」に企画メモを保存し、URL を伝える。
その後 1-b へ。

---

### 1-b. ジャンル識別

`references/article-types.md` の定義を参照し、ジャンル識別子（`python-impl` / `ai-story` / `dx-process` / `daily-hack`）を判定してユーザーに伝える。

### 1-c. ブランド整合確認

以下の観点で自己評価し、**懸念がある場合のみ**ユーザーに確認する。

- この記事はブランド軸「製造現場の課題を調査から実装まで」に沿っているか
- 記事を通じて「現状調査→可視化→設計→実装→運用」のプロセスの一部が見えるか
- `daily-hack` や製造業から大きく離れたテーマの場合、それでも発信する意図があるかを確認する

懸念なし、またはユーザーの確認が取れたら Step 2 へ。

---

## Step 2: 一次情報ヒアリング

テンプレートを使わない。
企画メモとジャンルを踏まえて「この記事を書くために何が不足しているか」を考え、質問を 1 問ずつ生成する。
すでに企画メモに書かれている情報は聞き直さない。

**どのジャンルでも必ず揃える（一次情報の三本柱）：**

以下が企画メモに不足している場合は、それを引き出す質問を必ず含める。

| 柱 | 内容例 |
|---|---|
| 実数・実測値 | 順位・スコア・時間・改善率・件数 |
| 失敗談・行き詰まり | うまくいかなかったアプローチ・判断ミス |
| 具体的なやり取り・場面 | 読者が「自分も同じだ」と感じる固有のシーン・セリフ |

三本柱が揃っていない状態で執筆しない。揃ったら「では執筆します」と伝えて Step 3 へ。

---

## Step 3: 執筆

CLAUDE.md の発信スタイル・文体ルールに従う。

### 3-a. ジャンル別記事の型を適用

`references/article-types.md` の該当ジャンルの型に従う。
型の順序は守るが、各セクションの分量・表現はテーマに合わせて調整してよい。

### 3-b. 一次情報の組み込み

Step 2 で得た三本柱を必ず本文に埋め込む。

- 実数のない段落は書かない
- 失敗談のない成功談は書かない
- やり取りや具体シーンのない AI 活用記事は書かない

### 3-c. 公開前チェックリスト（執筆時点で対応できる項目）

CLAUDE.md の「記事制作のチェックリスト（公開前）」を参照し、執筆段階で対応できる項目（対象読者の明示・Mermaid 図の使用など）を確認する。

`articles/[slug].md` を作成または更新したら Step 4 へ。

---

## Step 4: レビューループ（最大 3 回）

### ループ変数
- `review_count` = 0（最大 3）

### 4-a. レビューサブエージェント起動

`Agent` ツールでサブエージェントを起動し、以下のプロンプトを渡す。

```
あなたは Zenn 記事のレビュアーです。
まず `.claude/commands/references/article-types.md` を読んでジャンルを確認してください。
次に以下の採点基準で記事を評価してください。

【採点基準（合計 100 点）】

A. タイトル（25点）
  - 製造業DX関連の検索需要があるキーワードを含む（10点）
    ※過去の実績参考：「Notion/Claude MCP」系→150PV、「外観検査」系→91PV、一般Pythonチュートリアル→30PV
  - 「これ自分の話だ」と感じる現場感・具体性（10点）
  - 数字・対比・問いかけなど注目を引く構造（5点）

B. リード文（20点）
  - 最初の3文で「共感→問題→解決の予告」が揃っている（10点）
  - 「誰のための記事か」が明示されている（10点）

C. 記事構成（20点）
  - article-types.md の該当ジャンルの型に沿っている（10点）
  - Before→After または 課題→対応が対になっている（10点）

D. 差別化・現場感（20点）
  - 「現場を知っている人間が書いている」と伝わる固有エピソードがある（10点）
  - まとめが表だけで終わらず、記事全体の主張を締める一文がある（10点）

E. 一次情報の密度（15点）
  - 実数・実測値が本文に入っている（5点）
  - 失敗談・行き詰まりエピソードがある（5点）
  - 具体的なやり取り・場面・セリフがある（5点）

【出力形式】
総合スコア: XX/100

| セクション | 点数 | 評価 |
|---|---|---|
| A. タイトル | XX/25 | ... |
| B. リード文 | XX/20 | ... |
| C. 記事構成 | XX/20 | ... |
| D. 差別化・現場感 | XX/20 | ... |
| E. 一次情報の密度 | XX/15 | ... |

優先修正箇所（点数が低い順に最大3件）:
1. [セクション名] — 問題：... / 修正案：...
2. ...

タイトル改善案（3案）:
1. ...
2. ...
3. ...

【記事】
[articles/[slug].md の全文]
```

### 4-b. レビュー結果を提示

サブエージェントの結果をそのままユーザーに表示する。

### 4-c. 修正ヒアリング

以下を聞く：

```
上記の修正点について：
- 対応する場合はどれを直しますか？（番号で）
- 他に直したい点はありますか？
- このまま公開してもよければ「OK」と教えてください。
```

### 4-d. 修正実行

ユーザーの指示に従って記事を修正する。修正後 `review_count += 1`。

### 4-e. ループ判定

- ユーザーが「OK」「このまま」「公開する」→ Step 5 へ
- `review_count >= 3` → 「3回のレビューが完了しました」と伝えて Step 5 へ
- それ以外 → 4-a に戻る

---

## Step 5: X投稿草案 & 公開準備

### 5-a. X草案サブエージェント起動

`Agent` ツールで X 投稿スレッド草案を生成する。

```
以下の Zenn 記事をもとに、X（Twitter）の投稿スレッド草案を作成してください。

【スレッド構成（4〜5ツイート、各140字以内）】
1. フック：記事の核心を一言で（体験談ベース・数字を入れる）
2. 問題提起：「こんな現場ありませんか？」で共感を引く現場あるある
3. 解決策の核心：アプローチを1〜2文で。難しくしない
4. 結果・インパクト：「やってみた結果〇〇だった」（具体的な数字を使う）
5. 記事への誘導：「詳しくはZennで👇」+ [URL後で入れる]
   ハッシュタグ：記事内容に合わせて選ぶ（例：#製造業DX #DX推進 #AI活用 #Python）

【記事】
[articles/[slug].md の全文]
```

### 5-b. X草案を Notion に保存

対応する企画メモページの子ページとして保存する。
ページタイトル：`🐦 X投稿草案｜[記事タイトル]`

企画メモが見つからなければ Zenn 運営タスクリスト（`3384732e-00f3-8136-9dac-c7b8d0bcbaaa`）直下に保存する。

### 5-c. 公開確認

以下を伝えてユーザーの確認を取る：

```
X投稿草案をNotionに保存しました: [URL]

記事を公開しますか？
→「公開する」と言えば published: true に変更します。
```

ユーザーが承認したら `published: false` を `published: true` に変更する。
